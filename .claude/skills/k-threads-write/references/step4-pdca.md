# 步驟 4 細節｜PDCA 優化：檢查、定稿、下一輪

SKILL.md 裡有這一步的流程跟要交的表。
這個檔放三層檢查的完整內容、紅線表、AI 味檢查表、交稿自查。

用 PDCA 跑一輪，**一次只改一個主要的地方**。
一次改太多，下次你根本分不出是哪個動作有效。

- **P 計畫**：寫一句——「這輪我想改善＿＿，看＿＿就知道有沒有改善」。內容訊號（觸及、留言、私訊分享）跟商業訊號（詢問、付款）分開看
- **D 執行**：先重新分配材料，再分層修：目的跟主張 → 材料跟推論 → 段落順序 → 句子跟語氣 → 版面跟結尾。上面那層沒穩，下面先別動
- **C 檢查**：發之前跑下面三層；發之後只看 P 挑定的那個訊號，讀者原話留著，還沒回饋的標「待觀察」，樣本太少就別急著當規律
- **A 調整**：用步驟 3 的模式 C 把取捨理由留下來；下一輪的題目，從讀者問過的問題、你砍掉的段落、舊文重製裡找；最後寫一個小動作

檢查的順序：先看判斷標準 → 再看主張・證據・邏輯 → 最後跑交稿自查。
這篇沒有寫作摘要，就從草稿倒推讀者、素材、任務、指定度，寫在報告最前面，標「反推」。

---

## 第一層：判斷標準

- **A 素材真實性**：逐段標生活／經歷／專業；分清事實、觀察、推論、假設；把這幾種抓出來——編造的數據客戶成效、把別人經歷寫成第一人稱、把一次觀察放大成「大家都」；數字要說清楚是算什麼、哪段時間、跟什麼比
- **B 指定的那一度**：只檢查指定的那一度；其他兩度不打分，但明顯錯誤還是要指出來
- **C 信任三角**：單篇標主要累積哪一角；批次檢查時統計分布，哪裡失衡講出來

---

## 第二層：主張・證據・邏輯跟版面

| 項目 | 看什麼 |
|---|---|
| 主張 | 前 3 行就出現、25 字內講完、是個結論 |
| 證據 | 每個論點都有素材，不要用形容詞代替 |
| 邏輯 | 只讀每段第一句，能不能串起來 |
| 開頭 | 讀者認得出自己、正文兌現得了 |
| 結尾 | 只一個下一步、大小配合讀者的已知程度 |
| 重新整理 | 相關的放一起、雜訊砍掉 |
| 分層強調 | 最重要的那一句，獨立成一段 |

檢查 AI 協作稿的時候，拿原稿對照，把被 AI 改大的確定程度、新增的事實，找出來。

**傳播檢查（選用，只提示，不打分）：**
- **可轉述**：讀者能不能用一句話，把這篇轉述給別人？最值得帶走的是哪一句？
- **分享動機**：這篇比較像「想私訊丟給某個人」「想公開轉一圈」「分享就是在表態」，還是「幫別人省時間」？私訊分享跟深度留言，是 Threads 最強的互動訊號
- **四種值得寫的文**：可轉傳／可討論（不是人人同意，但人人看得懂）／可套用（能對照自己）／可收藏（有框架）。**四種容易死的**：假深刻（句子漂亮但沒資訊）、假爭議（只挑釁不論證）、假原創（轉述別人的）、假互動（靠 CTA 硬拉）

## 第二層之一：Threads 演算法紅線

命中就**直接警告**：「這樣寫會被降權，確定要這樣發嗎？」
其他項目，用建議的語氣就好。

| # | 紅線 | 看什麼 |
|---|---|---|
| R1 | 討互動 | 要求按特定反應、分享、Tag → 警告。要求留言或留特定文字（「留言『要』」）→ 只提醒：會影響這篇觸及，任務是導流、領資源時可以用，別每篇都用，累積太多會拖累整個帳號。圖片裡的字也算 |
| R2 | 標題騙點擊 | 「99% 的人不知道」、過量驚嘆號、故意不講重點 |
| R3 | 首句跟正文不一致 | Hook 可以強，不能詐；首句承諾什麼，正文就要證明 |
| R4 | 搬運／低品質原創 | 跟自己近期貼文高度相似、轉述別人卻沒有自己的分析、結論、經驗或框架 |
| R5 | 連續同主題同角度 | 同領域可以；同角度、同結論換個包裝，不行 |
| R6 | 低品質外連 | 能在貼文內講清楚的，先講清楚 |
| R7 | 敏感主題聳動寫法 | 健康、財務不要寫得像保證結果；政治社會議題，表述要注意 |
| R8 | 容易引發「不感興趣」 | 首句聳動正文空、題目講 A 內容講 B、同一論點一直重講 |
| R9 | 主題混雜 | 一篇只打一個主題中心 |
| R10 | AI 寫實圖片／影片沒標示 | 提醒要標示 |
| R11 | 圖文不一致 | 圖要把重點視覺化、給證據、或讓人更好懂 |
| R12 | 軟性降權（命中 2 項以上才提醒） | 太像為演算法寫的、泛用廢話沒新資訊、連續幾篇都在講一樣的事 |

## 第二層之二：AI 味檢查

分成「確定」跟「可能」兩種。
**確定的，建議修改。可能的，交給作者自己判斷**——因為那有可能是他刻意的寫法。

| 層 | 確定 | 可能 |
|---|---|---|
| 語句 | 裝生動的固定句式 ≥ 2 個（「說白了就是」「想像一下」）；連續 2 句以上金句；自問自答的表演式轉折；句尾反問鎖結論；書面連接詞 ≥ 3；情緒標籤詞（令人震驚的是、值得深思）；哲理收尾 | 對比句前後字數太工整（「不是 X，而是 Y」）；一句話把現象＋原因＋推論全講完；列舉時每點的長度句式都一樣 |
| 結構 | 全篇零讓步零例外；末段同時做 2 件以上（結論＋建議＋CTA） | 超過一半段落都有段尾小結；完美的起承轉合；每段字數太平均 |
| 內容 | 數字沒來源又講得很確定；只有支持主論的證據；抽象判斷 ≥ 2 個卻沒案例 | 結論兩面討好；花一整段科普讀者早就知道的概念 |

**濃度：** 確定項 0–2 低／3–5 中（針對性修改）／6 以上高（建議大改）。

**怎麼把 AI 味降下來**（只用作者真的有的素材，缺的標【需補】）：
- 補一個具體案例
- 補一個自己判斷錯的地方（原本以為…後來發現…）
- 補一個例外
- 數字加上來源跟不確定性
- 留一句不漂亮的話
- 判斷留一點空隙，別把話說死
- 收尾只做一件事

**一條界線要講清楚：** 寫得整齊、用了修辭、邏輯清楚，這些都不等於 AI 味。
AI 味是什麼？
是好幾個訊號疊在一起，那種太均勻、太完整、太好預測的感覺。

## 第三層：交稿自查 10 項

- [ ] 讀者跟主要任務清楚
- [ ] 開頭能被正文兌現
- [ ] 一個主張，有具體支撐跟合理推論
- [ ] 事實、觀察、推論、假設，分得開
- [ ] 沒有編造數據、客戶、第一人稱經歷或成效
- [ ] 沒來源的說法，已經刪掉、縮小或補上材料
- [ ] 人設優先，公式配合作者
- [ ] 結尾承接正文；需要時只留一個主要的下一步
- [ ] 本人讀過每一句，知道哪些 AI 建議採用、哪些拒絕
- [ ] 原稿、改稿、關鍵修改理由，都留著

最後兩項，只有作者本人能確認。
標「待作者確認」，**不要替作者打勾**。

---

## 檢查的規矩

- 先把問題指出來，**不要自己動手把整篇重寫**；作者說「幫我改」，才給修改版，而且只動有問題的那幾句，語氣保留原樣
- 每個 ⚠️、❌，都要引用原句、給具體改法，不要寫「可以再加強」這種空話
- 證據不夠的時候，說清楚要補什麼素材，**不要替作者編**
