# K叔寫作流程

2027 Threads 文案寫作課｜AI 協作低摩擦文案。四個步驟對應四堂課：

| 步驟 | 對應 | 產出 | 使用者這樣說時 |
|---|---|---|---|
| 1 寫作摘要 | 第 1 堂 | TA 六格、一頁寫作摘要 | 要寫一篇、這篇寫給誰、TA 分析、定目標 |
| 2 文案拆解 | 第 2 堂 | Hook＋內容＋CTA 結構表、拆解報告 | 排結構、大綱、拆這篇、給我 Hook、CTA 怎麼寫 |
| 3 AI 協助產出 | 第 3 堂 | 風格卡、素材盤點、3 個開頭、2 版初稿、取捨清單 | 寫初稿、寫成我的口氣、建風格卡 |
| 4 PDCA 優化 | 第 4 堂 | 改善目標、檢查報告、交稿自查 10 項、下一輪計畫 | 幫我檢查、改稿、交稿前檢查、為什麼沒人看、復盤 |

**怎麼跑：** 判斷使用者在哪一步，就從那一步開始；前一步的產出缺了，先補最少必要的欄位（讀者情境、素材、主要任務、指定度、核心主張），補不齊標【假設】繼續。使用者說「整套」「從頭寫」，就 1→4 依序跑，每一步結束停下來讓作者確認再往下。

**分工：** AI 整理材料、提出選項與初稿、指出問題；作者決定讀者、主張、取捨與定稿。

## 寫作目標：Threads 為主，官網 SEO 長文為輔

這套流程**預設是 Threads 短文**；四步、風格卡、字數（50–200 字）與斷行規則都以 Threads 為準。

當作者要寫的是**官網部落格／SEO 長文**（例如 runing9to5.com）時，整體流程與判斷標準不變，只套用這些調整：

| 項目 | Threads（預設） | 官網 SEO 長文 |
|---|---|---|
| 排版 | 風格卡斷行（空格代逗號、換行代句號） | **正常段落＋ `##` 標題**，不套 Threads 斷行 |
| 字數 | 50–200 字 | 放寬（常見 1,200–2,000 中文字） |
| 步驟 1 多一欄 | — | **目標關鍵字＋搜尋意圖**（這篇要吃哪個詞、搜的人想要什麼） |
| 步驟 2 支持點 | 1–3 個 | 3–6 個（一個 `##` 對一個支持點） |
| 產出要帶 | 貼文正文 | title／description／permalink（英文 slug）／站內連結 2–4 條／**FAQPage schema** |
| 語氣 | K叔口吻 | K叔口吻不變（第一人稱、具體、避 AI 味） |

官網的結構規範（slug、分類 taxonomy、Article／FAQPage schema、E-E-A-T）以 `SEO_RULES.md` 為準；本流程負責「寫得像 K叔、對準搜尋意圖、不踩 AI 味」。其餘 Threads 演算法紅線、AI 味檢測與交稿自查，兩種形式都照原樣適用。

一句話：**社群先、SEO 次；形式變，主張和證據不變。**

## 共用規則（四步都適用）

### 判斷標準

| 標準 | 元素 | 怎麼用 |
|---|---|---|
| 內容三件事 | 生活／經歷／專業 | 素材來源，必須是作者真的有的 |
| 內容三度 | 辨識度／專業度／價值度 | 依主要目的**指定一度**，發前只檢查這一度；任何文類都可以選任何一度 |
| 信任三角 | 熟悉感／親切感／價值感 | 長期觀察用；不打分數，也不當發文配額 |

| 度 | 發前檢查 | 讀者感受 |
|---|---|---|
| 辨識度 | 有沒有作者的選擇或經驗，遮掉名字也認得出 | 我記得你 |
| 專業度 | 有沒有說清楚判斷理由、方法或適用條件 | 我覺得你懂 |
| 價值度 | 讀者讀完能多做哪個判斷，或完成哪一步 | 我覺得有用 |

### 硬規則

- **不編造**數據、客戶、第一人稱經歷、成效、讀者原話。缺的標【需補：＿＿】
- **不把確定程度改大**：「還在嘗試」不能寫成「已經證實」
- 分清楚**事實**（能核對）／**觀察**（特定範圍看到的）／**推論**（可能的解釋）／**假設**（待確認）
- 示範情境寫明「示範」，不能寫成作者實績
- **作者的人設優先**：學員不寫成 K叔；K叔風格卡只在作者是 K叔時用
- **自然停點可以沒有 CTA**；服務說明文要說清楚方案與下一步；有下一步時只放一個
- 避開 AI 句型：「不是 X，是 Y」對仗、連續格言、哲學式收尾、結尾同時塞結論＋建議＋CTA、書面連接詞（然而、值得注意的是、換言之）
- 字數以 50–200 字作練習參考，依任務調整
- 帳號定位、商品 A→B、引流、PDCA 的完整版在〈Threads 低摩擦經營〉，兩門課互補；這裡處理單篇
- **問句收尾與留言 CTA**：開放式問題「你也會這樣嗎？」沒有風險。「留言告訴我」「留言『要』領資源」這類要求留言或特定文字的寫法會影響觸及，但可以用：任務是「行動」（領資源、導流）時，用觸及換名單是作者可以做的取捨，只提醒代價、不當錯誤；不要每篇都用。「按讚如果你同意」「分享給朋友」「Tag 一個人」不建議用（見步驟 4 R1）
- Threads 演算法、AI 味、心理學知識整理自 AK-Threads-booster（AK SEO Labs，MIT）。需要個人歷史數據的工作（選題、預測 24 小時表現、發文後復盤、更新數據）不在這個 Skill，用 AK-Threads-booster 本體

## 步驟 1｜寫作摘要（以終為始＋換位思考）

先想讀者看完要發生什麼，再回頭想他需要知道什麼，最後才動筆。寫之前從「我想說」換到「他想聽」：我想介紹方法 → 他卡在哪？我想證明專業 → 他要看到什麼才信？我想賣服務 → 他買之前會問什麼？

### 1-0 TA 六格（與低摩擦經營 1-5 共用）

帳號層級填一次，之後每篇挑一個情境。

| # | 欄位 | 寫什麼 | 用在哪 |
|---|---|---|---|
| 1 | 背景與日常 | 年齡、職業、一天的樣子、時間和能量、試過什麼 | 從哪講起、可省略什麼 |
| 2 | 問題點 | 他現在遇到的問題，具體到一個場景 | 開頭要碰到的感受 |
| 3 | 他說的話 | 留言、私訊、諮詢時的**原句** | 開頭與用詞 |
| 4 | 他喜歡的內容 | 會按讚、收藏、分享什麼；追蹤誰 | 表達方式、例子 |
| 5 | 他在意的問題 | 做決定前會問什麼、懷疑什麼 | 正文要回答的內容與順序 |
| 6 | 他跟你一樣的經歷 | 作者也走過的那一段 | 素材、辨識度、親切感 |

第 2 格是他現在卡住的地方，第 5 格是他做決定前想問的事。第 3 格沒有原句就標【需補】。

### 1-1 讀者一句話＋已知程度

> 我寫給正在＿＿的人，他已經＿＿，卻卡在＿＿，這篇先幫他＿＿。

已知程度：還沒察覺／知道問題不知方法／正在比較／準備開始。另寫「他想看的」（會點進來的問題）和「他需要看的」（他不知道但一定要講的）。

### 1-2 素材、切角、表達

- 素材（選一個來源，寫一行具體內容）：生活＝事件＋一個細節；經歷＝原本以為什麼 → 發生什麼 → 後來怎麼選；專業＝實際處理問題時的判斷或方法
- 切角：痛點／經驗／工具／錯誤／案例（一題五切角：同主題各寫一句，檢查是否在回答五個不同問題）
- 表達：共鳴／觀點／解法／娛樂／導購

### 1-3 文案目的三層＋主要任務

| 層 | 問自己 |
|---|---|
| 新的想法 | 他看完對這件事的看法怎麼變？ |
| 做出哪種決定 | 有了新想法，他會決定什麼？ |
| 採取哪些動作 | 這個決定變成什麼具體動作？（可以很小：收藏、留言） |

主要任務只選一個：看見、記住（偏新的想法）／信任（偏做出決定）／行動（偏採取動作）。

### 1-4 指定一度、信任三角、核心主張、結尾

- 指定一度：依主要目的選，和任務對得上
- 信任三角（觀察）：這篇主要希望讀者感受熟悉、親切或價值
- 核心主張：用「我希望讀者看完，知道＿＿」測試；要接五六個答案就太大
- 結尾：停在一個判斷，或一個和正文相連的下一步

### 步驟 1 輸出

```
## 寫作摘要｜〈主題〉
| 項目 | 內容 |
|---|---|
| TA 情境（六格挑一） | |
| 讀者 | 我寫給正在＿＿的人……（已知程度：＿＿） |
| 他想看的／他需要看的 | |
| 素材 | 生活／經歷／專業：〈一行〉（✅真實／📝示範／❓待補） |
| 切角／表達 | |
| 文案目的 | 想法：＿／決定：＿／動作：＿ |
| 主要任務 | |
| 指定一度 | |
| 信任三角（觀察） | |
| 核心主張 | |
| 結尾 | 判斷：＿ 或 下一步：＿ |
```

檢核：讀者是具體情境（不是年齡層＋興趣）；素材是真的；任務、指定度各一個；主張一句話能重述。

## 步驟 2｜文案拆解：Hook＋內容＋CTA

一篇文案拆成三塊：Hook 讓對的人停下來，內容推進理解、兌現 Hook，CTA 完成任務（對應開場、主體、結尾）。使用者貼一篇文要「拆解」時，標出三塊各用了哪種寫法、哪裡斷掉。同一篇選一個主骨架，工具名稱不放進成品。

| 段 | 要回答 | 檢查 |
|---|---|---|
| 開場 | 為什麼值得看下去？ | 讀者認得出自己、具體、正文接得住；前兩句就讓人知道主題 |
| 主體 | 讀者下一個需要理解的問題？ | 每段增加資訊、支持同一主張 |
| 結尾 | 讀完帶走什麼？ | 一個判斷或一個相連的下一步 |

### 主體骨架

依表達：共鳴＝場景→感受→被理解→提問；觀點＝普遍說法→不同觀點→理由→結論；解法＝問題→方法→例子→小行動；娛樂＝設定→期待→反轉→笑點；導購＝卡點→原因→解法→商品→下一步（附真實證據與適用條件）。

十五組邏輯工具（先熟練 1、4、8，其他需要時查）：

| # | 工具 | 適合 | 常見錯誤 |
|---|---|---|---|
| 1 | 結論→理由→事實 | 有明確觀點 | 只有立場沒有可檢查的材料 |
| 2 | 現狀→理想→落差→解法 | 看見要改哪一段 | 落差寫「不夠努力」 |
| 3 | 問題→解決方案 | 短教學 | 原因未明就給通用答案 |
| 4 | 現況問題→原因→對策 | 拆解卡點 | 對策沒對應原因 |
| 5 | 連問五個為什麼 | 追到具體問題 | 每層由 AI 猜答案 |
| 6 | 假設→驗證→結果 | 分享實驗 | 把打算做的寫成已完成 |
| 7 | 可能原因→驗證→結果→對策 | 多個解釋的問題 | 太快歸到最熟的答案 |
| 8 | 改善前→改善後→差異 | 改稿示範、案例 | 從改一句直接跳到成交增加 |
| 9 | PDCA | 持續練習 | 一次改很多處 |
| 10 | 回顧（KPT） | 週報、反思 | 只寫「繼續努力」 |
| 11 | 提案：目的→概念→比較→效益→行動→案例 | 服務、課程提案 | 未確認的價格班期寫成承諾 |
| 12 | 價值主張：提供什麼→給誰→價值 | 自介、服務開頭 | 協助放大成保證 |
| 13 | 矩陣 | 比較方案 | 判斷寫成精確分數 |
| 14 | SWOT | 盤點 | 沒接到行動 |
| 15 | 5W2H | 把模糊問題寫清楚 | 當固定欄位硬填 |

### 每個支持點 4 欄

讀者的問題（問句）／關鍵訊息（完整句、有結論）／素材【生活】【經歷】【專業】／真實性（✅ 真實／📝 示範／❓ 待補）。

指定辨識度→主體至少一個【生活】或【經歷】；專業度→至少一處理由、方法或限制；價值度→至少一處讀者能照做。

### 開頭的心理機制（選入口時參考）

| 機制 | 怎麼用 | 注意 |
|---|---|---|
| 資訊缺口 | 讀者「大概知道但不確定」時最有效 | 缺太多覺得無關，缺太少沒懸念 |
| 具體數字 | 阿拉伯數字、對應正文 | 數字要有來源，不編 |
| 模式打斷 | 反直覺的開場、和讀者預期不同的資訊 | 反直覺要證得出來 |
| 打開一個迴路 | 先拋問題、稍後解答 | 每個懸念都要在正文關上 |
| 峰終定律 | 全篇一個情緒峰值，結尾不虎頭蛇尾 | 峰值和結尾比長度重要 |

**Hook／兌現落差**：開頭太強、正文兌現太弱最危險。讀者只讀前 30%，就要已經拿到一個可帶走的重點。

### Hook 寫法

- 七種基本入口：結論型／反問提問型／數字型／利益型／情緒＋問題型／情境型／資訊缺口型
- 故事文六種入口：場景觸發／他人言語（只用真的說過的話）／回顧反思／反問／問答／假設對比
- K叔開頭公式見步驟 3 風格卡（作者是 K叔時才直接用）
- 條件：相關、具體、正文能回答；第一行能單獨成立；不碰紅線 R2、R3

### CTA 寫法

- 五種基本型：思考型／經驗型／行動型／收藏型／轉換型
- 四種收法：觀點收束（不放 CTA）／教學行動／經驗邀請／服務入口
- 互動設計：留言（提問、選擇、分享式）／收藏（清單、工具、直說）／轉傳（情緒共鳴、實用、破框架）
- 導流入口：主頁、文末、留言私訊；私域路徑：免費資源或電子報 → 低價產品 → 諮詢 → 陪跑
- 大小配合已知程度：剛認識問題→小檢查、收藏；知道卡點→完整資源；正在比較→範圍與案例；準備開始→預約、購買
- 一篇一個主要下一步；不要每篇固定問「大家怎麼看」；R1 規則見共用規則

篇幅：Threads 短文、單張圖卡 1 個支持點；長文、輪播、口播 2–3；電子報、服務說明 3–5。換形式時主張和證據不變。

### 步驟 2 輸出

```
## 結構表｜〈主題〉
摘要：讀者＝｜素材＝｜表達＝｜任務＝｜指定度＝｜骨架＝
開場｜Hook：　脈絡：　預告：（短文可省）
主體
| 讀者的問題 | 關鍵訊息 | 素材 | 真實性 |
結尾｜收束：
```

檢核：只讀關鍵訊息能串成一篇（沒有跳步、重複、離題）；開頭的問題正文有回答。

## 步驟 3｜AI 協助產出

三種模式：A 建風格卡／B 寫初稿／C 協作紀錄。沒有風格卡先問要不要建（或請作者貼 3–5 篇舊文）；作者不在就用平實具體的語氣寫，註明「未套用風格卡」。

### 模式 A｜建風格卡

輸入作者確認可用的 5–10 篇代表作（盡量涵蓋人設、知識、銷售）。只寫看得到的特徵，每項指回一句原文，看不出來的留空。

欄位：開頭習慣／句長與斷行／標點與排版／常用詞／不會用的詞／怎麼下判斷／轉折方式／收尾方式／emoji 與 hashtag／開頭公式（選用）。最後列「待作者確認」。

### 模式 B｜寫初稿

1. **固定與可變**：核心主張、已知事實、服務範圍、指定度不能改；開頭入口、表達、長度、結尾形式可以改
2. **素材盤點**：已知事實／作者主張／缺少的資料（【需補】，不讓 AI 補）
3. **三個開頭**：不同入口（結論、提問、情境、利益、資訊缺口、數字），各註明正文要兌現什麼
4. **兩版初稿**：差異在開頭入口或骨架，只換字不算；套用風格卡；做到指定度
5. **來源對照**：每段標素材來源、事實／觀察／推論／假設、AI 新增了什麼
6. **自查**：不像作者的詞、AI 句型、超出素材的數字或結果
7. **取捨清單**：選哪個開頭、哪幾句請作者確認像不像自己（列出原句）、【需補】要補什麼、順序要不要調

### 模式 C｜協作紀錄

| 段落 | 原稿或指令 | AI 輸出 | 作者定稿 | 採用／拒絕 | 理由 |

至少一項採用、一項拒絕。理由由作者說，AI 不代填。

### K叔風格卡（作者是 K叔時才用）

| 項目 | 規則 |
|---|---|
| 開頭 | 第一行以 12 字內為參考，反問、自我揭露或觀察 |
| 斷行 | 一行只講一件事；空格代替逗號、換行代替句號；段落間空一行 |
| 轉折 | 「其實…」「後來才發現…」；不用「不是 X，是 Y」 |
| 常用詞 | 聊天室、海巡、信任、說人話、先交友再交易、厭世、大叔 |
| 符號 | 不用 hashtag；emoji 最多一個；條列用 1.／・／→ |
| 收尾 | 適合時一個開放式問題；需要導流時只放一個入口；自然停點可不放 |
| 內容 | 至少一個具體場景；不編數字 |

開頭公式（選用）：你有沒有發現…／是不是覺得…對，沒錯。／我有個壞習慣…你也會這樣嗎？／我先說 1. 2. 3.／很多人把 X 當成 Y／焦慮翻轉…你們說 對不對!!／我看過這麼多帳號…／有沒有人想＿＿（補上商品＋下一步）。

真實取捨範例：AI 初稿「我發現自己有一個小小的壞習慣，每當有人按讚的時候，我都會忍不住點進去看看對方的頁面。」→ 句子太長；「小小的」「忍不住」不像本人，刪掉；把「我有個壞習慣」拉到第一行；結尾補問題 → 定稿：「我有個壞習慣／有人按讚 留言 會是追蹤／就會去你的頁面看一下／你也會這樣嗎？」

## 步驟 4｜PDCA 優化：檢查、定稿與下一輪

用 PDCA 跑一輪，一次只改一個主要因素：

- **P 計畫**：寫一句「這輪我想改善＿＿，看＿＿就知道有沒有改善」；內容訊號（觸及、留言、私訊分享）和商業訊號（詢問、付款）分開
- **D 執行**：先重新分配材料，再分層修稿：目的與主張 → 材料與推論 → 段落順序 → 句子與語氣 → 版面與結尾，上層沒穩下層先不修
- **C 檢查**：發前跑下面三層；發後只看 P 選定的訊號，保留讀者原話，沒有回饋標「待觀察」，樣本少不當規律
- **A 調整**：用步驟 3 模式 C 留下取捨理由；下一輪從讀者問過的問題、刪掉的段落、舊文重製來；寫下一個小動作

先看判斷標準，再看主張・證據・邏輯，最後跑交稿自查。沒有寫作摘要時，從草稿反推讀者、素材、任務、指定度，寫在報告開頭標「反推」。

### 第一層：判斷標準

- **A 素材真實性**：逐段標生活／經歷／專業；分清事實、觀察、推論、假設；標出編造的數據客戶成效、把別人經歷寫成第一人稱、把一次觀察擴大成「大家都」；數字要說清楚算什麼、哪段時間、和什麼比
- **B 指定的那一度**：只檢查指定的那一度；其他兩度不打分，但明顯錯誤照樣指出
- **C 信任三角**：單篇標主要累積哪一角；批次檢查時統計分布，指出失衡

### 第二層：主張・證據・邏輯與版面

主張（前 3 行出現、25 字內講完、是結論）／證據（每個論點有素材，不用形容詞代替）／邏輯（只讀每段第一句能串起來）／開頭（讀者認得出自己、正文兌現）／結尾（只一個下一步、大小合已知程度）／重新整理（相關放一起、刪雜訊）／分層強調（最重要的一句獨立成段）。

檢查 AI 協作稿時，對照原稿，找出被 AI 改大的確定程度和新增的事實。

傳播檢查（選用，只提示不打分）：
- **可轉述**：讀者能不能用一句話轉述給別人？最值得帶走的是哪一句？
- **分享動機**：更像「想私訊丟給某個人」、「想公開轉一圈」、「分享就是表態」，還是「幫別人省時間」？私訊分享和深度留言是 Threads 最強的互動訊號
- **四種值得寫的文**：可轉傳／可討論（不是人人同意但人人看得懂）／可套用（能對照自己）／可收藏（有框架）。四種容易失敗的：假深刻（句子漂亮沒資訊）、假爭議（只挑釁不論證）、假原創（轉述別人）、假互動（靠 CTA 硬拉）

### 第二層之一：Threads 演算法紅線

命中就直接警告：「這樣寫會被降權，確定要這樣發嗎？」其他項目用建議語氣。

| # | 紅線 | 看什麼 |
|---|---|---|
| R1 | 討互動 | 要求按特定反應、分享、Tag → 警告。要求留言或留特定文字（「留言『要』」）→ 只提醒：會影響這篇觸及，任務是導流、領資源時可以用，別每篇都用，累積太多會影響整個帳號。圖片裡的字也算 |
| R2 | 標題騙點擊 | 「99% 的人不知道」、過量驚嘆號、故意不講重點 |
| R3 | 首句和正文不一致 | Hook 可以強，不能詐；首句承諾什麼，正文就要證明 |
| R4 | 搬運／低品質原創 | 和自己近期貼文高度相似、轉述別人沒有自己的分析、結論、經驗或框架 |
| R5 | 連續同主題同角度 | 同領域可以；同角度、同結論換包裝不行 |
| R6 | 低品質外連 | 能在貼文內講清楚的先講清楚 |
| R7 | 敏感主題聳動寫法 | 健康、財務不要像保證結果；政治社會議題要注意表述 |
| R8 | 容易引發「不感興趣」 | 首句聳動正文空、題目講 A 內容講 B、同論點一直重講 |
| R9 | 主題混雜 | 一篇只打一個主題中心 |
| R10 | AI 寫實圖片／影片未標示 | 提醒標示 |
| R11 | 圖文不一致 | 圖要視覺化重點、提供證據或提高理解 |
| R12 | 軟性降權（命中 2 項以上才提醒） | 太像為演算法寫、泛用廢話沒新資訊、連續幾篇講一樣的事 |

### 第二層之二：AI 味檢測

分「確定」和「可能」：確定的建議修改，可能的由作者自己判斷（可能是刻意的寫法）。

| 層 | 確定 | 可能 |
|---|---|---|
| 語句 | 裝生動的固定句式 ≥ 2 個（「說白了就是」「想像一下」）；連續 2 句以上金句；自問自答的表演式轉折；句尾反問鎖結論；書面連接詞 ≥ 3；情緒標籤詞（令人震驚的是、值得深思）；哲理收尾 | 對比句前後字數太工整（「不是 X，而是 Y」）；一句話把現象＋原因＋推論講完；列舉每點長度句式都一樣 |
| 結構 | 全篇零讓步零例外；末段同時做 2 件以上（結論＋建議＋CTA） | 超過一半段落有段尾小結；完美起承轉合；每段字數太平均 |
| 內容 | 數字沒來源又講得很確定；只有支持主論的證據；抽象判斷 ≥ 2 個沒案例 | 結論兩面討好；花一整段科普讀者已知的概念 |

濃度：確定項 0–2 低／3–5 中（針對性修改）／6 以上高（建議大改）。

降 AI 味的方法（只用作者真的有的素材，缺的標【需補】）：補一個具體案例；補一個自己判斷錯的地方（原本以為…後來發現…）；補一個例外；數字加上來源與不確定性；留下不漂亮的句子；判斷留一點空隙；收尾只做一件事。

邊界：寫得整齊、用了修辭、邏輯清楚都不等於 AI 味。AI 味是多個訊號疊起來的均勻感、完整感、可預測感。

### 第三層：交稿自查 10 項

- [ ] 讀者與主要任務清楚
- [ ] 開頭能由正文兌現
- [ ] 一個主張有具體支撐與合理推論
- [ ] 事實、觀察、推論與假設分得開
- [ ] 沒有編造數據、客戶、第一人稱經歷或成效
- [ ] 沒有來源的說法已刪、縮小或補材料
- [ ] 人設優先，公式配合作者
- [ ] 結尾承接正文；需要時只留一個主要下一步
- [ ] 本人讀過每一句，知道哪些 AI 建議採用或拒絕
- [ ] 保存原稿、改稿與關鍵修改理由

最後兩項只有作者能確認，標「待作者確認」，不替作者打勾。

### 步驟 4 輸出

```
## PDCA 檢查｜〈首句〉
改善目標（P）：＿＿｜要看的訊號：＿＿（使用者沒給就問，或標「未設定」）
摘要：讀者＝｜素材＝｜任務＝｜指定度＝（沒給的標「反推」）
紅線警告（有命中才列，放最前面）
第一層｜項目｜判定 ✅/⚠️/❌｜問題句（引用原文）｜怎麼改
第二層｜同上
AI 味｜確定（引用原句→命中規則→修改方向）／可能／濃度
第三層｜交稿自查 10 項
最該先改的 3 件事（素材不實永遠排第一）
```

批次檢查另加：| 篇名 | 素材 | 指定度 | 是否達成 | 信任角 |

### 檢查規則

- 先指出問題，不主動重寫全文；使用者說「幫我改」才給修改版，只動有問題的句子，保留原語氣
- 每個 ⚠️、❌ 都引用原句、給具體改法，不寫「可以再加強」
- 證據不足時說明要補什麼素材，不替作者編
