# 步驟 4 細節｜PDCA 優化：檢查、定稿與下一輪

SKILL.md 有這一步的流程和輸出模板。這裡放三層檢查的完整內容、紅線表、AI 味檢測表與交稿自查。

用 PDCA 跑一輪，**一次只改一個主要因素**：

- **P 計畫**：寫一句「這輪我想改善＿＿，看＿＿就知道有沒有改善」。內容訊號（觸及、留言、私訊分享）和商業訊號（詢問、付款）分開
- **D 執行**：先重新分配材料，再分層修稿：目的與主張 → 材料與推論 → 段落順序 → 句子與語氣 → 版面與結尾。上層沒穩，下層先不修
- **C 檢查**：發前跑下面三層；發後只看 P 選定的訊號，保留讀者原話，沒有回饋標「待觀察」，樣本少不當規律
- **A 調整**：用步驟 3 模式 C 留下取捨理由；下一輪的題目從讀者問過的問題、刪掉的段落、舊文重製來；寫下一個小動作

檢查順序：先看判斷標準 → 再看主張・證據・邏輯 → 最後跑交稿自查。沒有寫作摘要時，從草稿反推讀者、素材、任務、指定度，寫在報告開頭標「反推」。

---

## 第一層：判斷標準

- **A 素材真實性**：逐段標生活／經歷／專業；分清事實、觀察、推論、假設；標出「編造的數據客戶成效」「把別人經歷寫成第一人稱」「把一次觀察擴大成『大家都』」；數字要說清楚算什麼、哪段時間、和什麼比
- **B 指定的那一度**：只檢查指定的那一度；其他兩度不打分，但明顯錯誤照樣指出
- **C 信任三角**：單篇標主要累積哪一角；批次檢查時統計分布，指出失衡

---

## 第二層：主張・證據・邏輯與版面

| 項目 | 看什麼 |
|---|---|
| 主張 | 前 3 行出現、25 字內講完、是結論 |
| 證據 | 每個論點有素材，不用形容詞代替 |
| 邏輯 | 只讀每段第一句能串起來 |
| 開頭 | 讀者認得出自己、正文兌現 |
| 結尾 | 只一個下一步、大小合已知程度 |
| 重新整理 | 相關放一起、刪雜訊 |
| 分層強調 | 最重要的一句獨立成段 |

檢查 AI 協作稿時，對照原稿，找出被 AI 改大的確定程度和新增的事實。

**傳播檢查（選用，只提示不打分）：**
- **可轉述**：讀者能不能用一句話轉述給別人？最值得帶走的是哪一句？
- **分享動機**：更像「想私訊丟給某個人」「想公開轉一圈」「分享就是表態」，還是「幫別人省時間」？私訊分享和深度留言是 Threads 最強的互動訊號
- **四種值得寫的文**：可轉傳／可討論（不是人人同意但人人看得懂）／可套用（能對照自己）／可收藏（有框架）。**四種容易失敗的**：假深刻（句子漂亮沒資訊）、假爭議（只挑釁不論證）、假原創（轉述別人）、假互動（靠 CTA 硬拉）

## 第二層之一：Threads 演算法紅線

命中就**直接警告**：「這樣寫會被降權，確定要這樣發嗎？」其他項目用建議語氣。

| # | 紅線 | 看什麼 |
|---|---|---|
| R1 | 討互動 | 要求按特定反應、分享、Tag → 警告。要求留言或留特定文字（「留言『要』」）→ 只提醒：會影響這篇觸及，任務是導流、領資源時可以用，別每篇都用，累積太多會影響整個帳號。圖片裡的字也算 |
| R2 | 標題騙點擊 | 「99% 的人不知道」、過量驚嘆號、故意不講重點 |
| R3 | 首句和正文不一致 | Hook 可以強，不能詐；首句承諾什麼，正文就要證明 |
| R4 | 搬運／低品質原創 | 和自己近期貼文高度相似、轉述別人沒有自己的分析、結論、經驗或框架 |
| R5 | 連續同主題同角度 | 同領域可以；同角度、同結論換包裝不行 |
| R6 | 低品質外連 | 能在貼文內講清楚的先講清楚 |
| R7 | 敏感主題聳動寫法 | 健康、財務不要像保證結果；政治社會議題要注意表述 |
| R8 | 容易引發「不感興趣」 | 首句聳動正文空、題目講 A 內容講 B、同論點一直重講 |
| R9 | 主題混雜 | 一篇只打一個主題中心 |
| R10 | AI 寫實圖片／影片未標示 | 提醒標示 |
| R11 | 圖文不一致 | 圖要視覺化重點、提供證據或提高理解 |
| R12 | 軟性降權（命中 2 項以上才提醒） | 太像為演算法寫、泛用廢話沒新資訊、連續幾篇講一樣的事 |

## 第二層之二：AI 味檢測

分「確定」和「可能」：**確定的建議修改，可能的由作者自己判斷**（可能是刻意的寫法）。

| 層 | 確定 | 可能 |
|---|---|---|
| 語句 | 裝生動的固定句式 ≥ 2 個（「說白了就是」「想像一下」）；連續 2 句以上金句；自問自答的表演式轉折；句尾反問鎖結論；書面連接詞 ≥ 3；情緒標籤詞（令人震驚的是、值得深思）；哲理收尾 | 對比句前後字數太工整（「不是 X，而是 Y」）；一句話把現象＋原因＋推論講完；列舉每點長度句式都一樣 |
| 結構 | 全篇零讓步零例外；末段同時做 2 件以上（結論＋建議＋CTA） | 超過一半段落有段尾小結；完美起承轉合；每段字數太平均 |
| 內容 | 數字沒來源又講得很確定；只有支持主論的證據；抽象判斷 ≥ 2 個沒案例 | 結論兩面討好；花一整段科普讀者已知的概念 |

**濃度：** 確定項 0–2 低／3–5 中（針對性修改）／6 以上高（建議大改）。

**降 AI 味的方法**（只用作者真的有的素材，缺的標【需補】）：
- 補一個具體案例
- 補一個自己判斷錯的地方（原本以為…後來發現…）
- 補一個例外
- 數字加上來源與不確定性
- 留下一句不漂亮的句子
- 判斷留一點空隙
- 收尾只做一件事

**邊界：** 寫得整齊、用了修辭、邏輯清楚都不等於 AI 味。AI 味是多個訊號疊起來的「均勻感、完整感、可預測感」。

## 第三層：交稿自查 10 項

- [ ] 讀者與主要任務清楚
- [ ] 開頭能由正文兌現
- [ ] 一個主張有具體支撐與合理推論
- [ ] 事實、觀察、推論與假設分得開
- [ ] 沒有編造數據、客戶、第一人稱經歷或成效
- [ ] 沒有來源的說法已刪、縮小或補材料
- [ ] 人設優先，公式配合作者
- [ ] 結尾承接正文；需要時只留一個主要下一步
- [ ] 本人讀過每一句，知道哪些 AI 建議採用或拒絕
- [ ] 保存原稿、改稿與關鍵修改理由

最後兩項只有作者能確認，標「待作者確認」，**不替作者打勾**。

---

## 檢查規則

- 先指出問題，**不主動重寫全文**；使用者說「幫我改」才給修改版，只動有問題的句子，保留原語氣
- 每個 ⚠️、❌ 都引用原句、給具體改法，不寫「可以再加強」這種空話
- 證據不足時說明要補什麼素材，**不替作者編**
