# 步驟 2 細節｜文案拆解：Hook＋內容＋CTA

SKILL.md 裡有這一步的目的跟要交的表。
這個檔放骨架庫、邏輯工具、Hook／CTA 的寫法跟範例。

一篇文，拆成三塊：
**Hook** 讓對的人停下來。
**內容** 把他往前帶、把 Hook 承諾的兌現掉。
**CTA** 把這篇要做的事收尾。
對應開場、主體、結尾。

| 段 | 要回答的問題 | 檢查 |
|---|---|---|
| 開場 | 為什麼值得看下去？ | 讀者認得出自己、具體、正文接得住；前兩句就讓人知道主題 |
| 主體 | 讀者下一個需要理解的問題是什麼？ | 每段都加新資訊、都撐同一個主張 |
| 結尾 | 讀完帶走什麼？ | 一個判斷，或一個連得起來的下一步 |

## 主體骨架（看表達挑）

| 表達 | 骨架 |
|---|---|
| 共鳴 | 場景 → 感受 → 被理解 → 提問 |
| 觀點 | 普遍說法 → 不同觀點 → 理由 → 結論 |
| 解法 | 問題 → 方法 → 例子 → 小行動 |
| 娛樂 | 設定 → 期待 → 反轉 → 笑點 |
| 導購 | 卡點 → 原因 → 解法 → 商品 → 下一步（附真實證據跟適用條件） |

## 十五組邏輯工具

先把 1、4、8 練熟。
其他的，需要的時候再回來查，不用背。

| # | 工具 | 適合 | 常見錯誤 |
|---|---|---|---|
| 1 | 結論→理由→事實 | 有明確觀點 | 只有立場，沒有可檢查的材料 |
| 2 | 現狀→理想→落差→解法 | 看清楚要改哪一段 | 落差寫成「不夠努力」 |
| 3 | 問題→解決方案 | 短教學 | 原因還沒搞清楚就給通用答案 |
| 4 | 現況問題→原因→對策 | 拆解卡點 | 對策沒對應到原因 |
| 5 | 連問五個為什麼 | 追到具體問題 | 每一層都讓 AI 去猜答案 |
| 6 | 假設→驗證→結果 | 分享實驗 | 把「打算做的」寫成「已完成的」 |
| 7 | 可能原因→驗證→結果→對策 | 有多個解釋的問題 | 太快歸到自己最熟的那個答案 |
| 8 | 改善前→改善後→差異 | 改稿示範、案例 | 從「改一句」直接跳到「成交增加」 |
| 9 | PDCA | 持續練習 | 一次改太多處 |
| 10 | 回顧（KPT） | 週報、反思 | 只寫「繼續努力」 |
| 11 | 提案：目的→概念→比較→效益→行動→案例 | 服務、課程提案 | 還沒確認的價格班期，寫成承諾 |
| 12 | 價值主張：提供什麼→給誰→價值 | 自介、服務開頭 | 把「協助」放大成「保證」 |
| 13 | 矩陣 | 比較方案 | 把判斷寫成精確分數 |
| 14 | SWOT | 盤點 | 盤完沒接到行動 |
| 15 | 5W2H | 把模糊問題寫清楚 | 當成固定欄位硬填 |

## 每個支持點，填這 4 欄

拆主體的時候，每個支持點都填這四格：

**讀者的問題（用問句）／關鍵訊息（完整句、有結論）／素材【生活】【經歷】【專業】／真實性（✅真實／📝示範／❓待補）**

看你指定哪一度，主體就要對應：
- 指定**辨識度** → 主體至少一個【生活】或【經歷】
- 指定**專業度** → 至少一處講清楚理由、方法或限制
- 指定**價值度** → 至少一處讀者能照著做

## 開頭的心理機制（挑入口時參考）

| 機制 | 怎麼用 | 注意 |
|---|---|---|
| 資訊缺口 | 讀者「大概知道但不確定」時最有效 | 缺太多覺得跟我無關，缺太少又沒懸念 |
| 具體數字 | 用阿拉伯數字，而且要對應正文 | 數字要有來源，不准編 |
| 模式打斷 | 反直覺的開場、跟讀者預期不一樣的資訊 | 反直覺，要證得出來 |
| 打開一個迴路 | 先拋問題，稍後解答 | 每一個懸念，都要在正文裡關上 |
| 峰終定律 | 全篇一個情緒高點，結尾不要虎頭蛇尾 | 高點跟結尾，比長度重要 |

**最危險的一種：Hook 跟兌現落差。**
開頭寫得超強，正文卻兌現得很弱。
記住，讀者只讀前 30%。
那 30% 裡，他就要已經拿到一個可以帶走的重點。

## Hook 寫法

**七種基本入口：** 結論型／反問提問型／數字型／利益型／情緒＋問題型／情境型／資訊缺口型

**故事文六種入口：** 場景觸發／他人言語（只用真的說過的話）／回顧反思／反問／問答／假設對比

**條件：** 相關、具體、正文回答得了；第一行要能單獨成立；不要碰紅線 R2（騙點擊）、R3（首句跟正文不一致）。
K叔的開頭公式在 step3-draft.md，作者本人是 K叔的時候才直接拿來用。

### Hook 範例庫（主題＝「發文沒人看」）

| 入口 | 範例 | 正文要兌現什麼 |
|---|---|---|
| 結論型 | 發文沒人看，通常不是你沒料，是第一行在自言自語 | 示範怎麼把「自言自語」改成「對著讀者說」 |
| 反問提問型 | 你發文前，會先想「這句話誰會看到」嗎？ | 給一個發文前的自問清單 |
| 數字型 | 我前 30 篇總共 12 個讚，第 31 篇改了一件事 | 說清楚那一件事是什麼 |
| 利益型 | 不用每天發，一週三篇也能被看見，重點在這一步 | 說明那一步是什麼 |
| 情緒＋問題型 | 發到想刪帳號的那天，我才發現問題不在頻率 | 說出真正的問題在哪 |
| 情境型 | 下班 9 點，打開草稿，寫三行又刪掉——是不是你？ | 給一個降低動筆門檻的方法 |
| 資訊缺口型 | 大部分人以為演算法在懲罰新帳號，其實卡在別的地方 | 講清楚到底卡在哪 |

## CTA 寫法

**五種基本型：** 思考型／經驗型／行動型／收藏型／轉換型

**四種收法：** 觀點收束（不放 CTA）／教學行動／經驗邀請／服務入口

**互動設計：**
- 留言：提問、選擇、分享式
- 收藏：清單、工具、直說
- 轉傳：情緒共鳴、實用、破框架

**導流入口：** 主頁、文末、留言私訊。
私域路徑：免費資源或電子報 → 低價產品 → 諮詢 → 陪跑

**CTA 多大，看讀者走到哪了：**

| 已知程度 | 適合的 CTA |
|---|---|
| 剛認識問題 | 小檢查、收藏 |
| 知道卡點 | 完整資源 |
| 正在比較 | 範圍跟案例 |
| 準備開始 | 預約、購買 |

**一個原則：** 一篇，一個主要的下一步。
不要每篇都固定問「大家怎麼看」，問久了讀者也麻了。
留言 CTA 的取捨，看 SKILL.md 的共用規則 R1。

### CTA 範例庫

| 型 | 範例 | 什麼時候用 |
|---|---|---|
| 思考型 | 下次發文前，先問自己一句：這第一行，是對著誰說的？ | 觀點、知識文自然收尾 |
| 經驗型 | 你也有發到想放棄的時候嗎？那篇後來怎麼了？ | 共鳴文，邀請分享 |
| 行動型 | 挑你最近一篇沒人看的，把第一行改成對讀者說說看 | 教學文，給一個小動作 |
| 收藏型 | 這個發文前三問，收藏起來，下次寫之前對一遍 | 有框架、有清單時 |
| 轉換型 | 想要完整的發文前檢查表，私訊「檢查表」我寄給你 | 任務是領資源／導流時（會換掉觸及，別每篇用） |

## 篇幅：要幾個支持點

| 形式 | 支持點 |
|---|---|
| Threads 短文、單張圖卡 | 1 個 |
| 長文、輪播、口播 | 2–3 個 |
| 電子報、服務說明 | 3–5 個 |

換形式的時候，主張跟證據不變，變的只是展開多少。

## 自己對一遍（步驟 2 做完）

- 只讀每個支持點的「關鍵訊息」，能串成一篇順的文（沒有跳步、重複、離題）
- 開頭丟出來的問題，正文有回答
- 主體有做到你指定的那一度
